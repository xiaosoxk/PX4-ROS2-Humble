# 任务分区与实时性设计（本项目的灵魂文档）

## 1. 为什么必须物理分区

Mavic 级航拍机 = 一台飞行器 + 一台 AI 计算机。让 AI 与飞控跑在同一个 CPU 上是
灾难设计：YOLO 推理的 GPU 抢占、Python GC、TensorRT 上下文切换都会造成毫秒级
卡顿，而 800Hz 姿态环的周期抖动预算只有 **几十微秒**。本项目的答案：

- **STM32H743（480MHz, NuttX）只做飞行**：IMU 采样→EKF3→控制→混控→DShot，
  全链路无动态内存、无文件系统、无阻塞调用；
- **Orin NX（8 核 A78AE + 1024 CUDA + NPU）只做 AI/视觉/通信**：崩溃、卡顿、
  重启都只是"一台风扇电脑的死机"，不伤及飞行；
- 两域之间只有一条 **单向窄带指令流**（MAVLink over UART 921600 或 ETH），
  AI 对飞行的影响上限 = "setpoint 停止更新"。

## 2. 硬实时域任务表（H743 / PX4）

| 任务 | 频率 | 优先级 | 说明 |
|---|---|---|---|
| IMU 采样中断 | 4kHz (ICM42688 ODR/8) | 最高 | 时间戳精确, 双 IMU 独立采样 |
| EKF3 多源融合 | 100Hz | 高 | 双 IMU 投票 + 气压 + 磁 + GNSS/RTK + 光流 |
| 角速率环 | 800Hz | 高 | MC_RATE_* PID, 输出直接进混控 |
| 姿态环 | 250Hz | 高 | 外环, 输出给角速率环 |
| 位置/速度环 | 50Hz | 中 | 位置控制包括 offboard setpoint 消费 |
| ai_gateway | 50Hz | 中低 | AI 网关裁决（见 firmware/px4_modules） |
| commander/failsafe | 事件+10Hz | 中高 | 失控/低电/围栏/堵转保护 |
| MAVLink 遥测 | 50Hz | 低 | TELEM2 → Orin |

## 4. 禁止 AI 抢占飞控时序的五道机制

1. **物理分区**：两颗芯片、两个操作系统。飞控域代码零依赖 AI 域；
2. **单向窄带**：AI 只能发 MAVLink setpoint（≤30Hz 指令流），进不了 1kHz 内环；
3. **双看门狗**：
   - Orin 侧 `safety_arbiter`：各 AI 节点 5Hz 心跳 + 延迟滑动审计，异常即断流；
   - 飞控侧 `ai_gateway`：500ms setpoint 流超时（R1），**这是 AI 域整体死亡时
     唯一需要的判据**，不需要对方配合；
4. **指令裁决**：倾角 35°/围栏 ±200m/高度 [2,120]m/速度 12m/s 全部在飞控侧
   二次校验（不信任任何来自 Orin 的数据）；
5. **资源隔离**：Orin 上 AI 节点 systemd `CPUWeight=200`、编码器独占 NVENC、
   MAVROS 线程 `SCHED_FIFO` 次高优先级；CUDA 上推理与编解码分用不同硬件单元。

## 5. 熔断状态机（两级）

```
[Orin 层] NORMAL --(心跳丢/延迟超/健康故障)--> FUSED: 停止转发 + 请求 POSCTL
[飞控层]  R1 流超时>500ms / R2 倾角 / R3 围栏 / R4 电量 --(连续3帧)--> 强制 POSCTL
```
两层任一独立成立都足以切断 AI。恢复：Orin 层健康 + 操作员确认（防震荡重连）。

## 6. 通信链路

- H743 TELEM2(921600 8N1) ↔ Orin ttyTHS0：MAVLink v2，飞控→Orin 50Hz 遥测包，
  Orin→飞控 ≤30Hz setpoint + 心跳；`bandwidth` 富余，CRC 天然内置；
- 备份：H743 以太网口 ↔ Orin 以太网（PX4 v1.14+ 支持 Ethernet MAVLink），
  UART 故障时切换（切换由双链路心跳仲裁，见故障排查手册 F09）。
